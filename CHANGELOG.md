# Events&I – changelog

## 2026-10-30

- [x] **Admin page and forms in the event's own time zone** — Date and time inputs, their labels and displayed times on the admin page follow the event's `timezone` ("UK time" for Europe/London, otherwise e.g. "New York time"); the booking form's closing time and opt-in session times and the manage page's session times do too. Checked in jsdom for an America/New_York event (inputs show and post the right instants) and in e2e.
- [x] **Messages to just the opt-in sessions** — The compose filter gains "Signed up for" (an opt-in session such as the dinner; people waiting for it only with the waiting-list box ticked) and two attendance choices that split "In person": "In person for the day" and "Only coming to opt-in sessions". "In person" itself still reaches both. e2e checks the counts.
- [x] **Review fixes for the booking-form polls and DMARC** — Poll totals count only confirmed registrations, so booking-form rankings from made-up addresses never sway them; a ranking made out of date while the form was open (poll closed, option gone) is dropped instead of blocking the registration, and only malformed answers are refused. Replies are refused only on DMARC `fail` or `permerror` (`none`, a domain without a policy, is common for small organisations), and an organiser's out-of-office is dropped before that check, so it never bounces. After a move only the ranking list is rebuilt, so its status region stays in place and screen readers announce the move. README notes that the form and its API must share a host for the Turnstile check.
- [x] **Calendar files in any time zone** — Events outside Europe/London were written in UTC; now every known IANA zone gets local times with a TZID and a VTIMEZONE built from the runtime's Intl data (each change of offset within a year of the event found by search and written as its own observance, so half-hour zones, zones without summer time and the southern hemisphere all work). Europe/London keeps its rule-based block; an unknown zone still falls back to UTC. Tests in `tests/ics.test.mjs`.
- [x] **Replaced hosts are asked to delete their lists** — When a session's host changes or is removed on the admin page, a previous host who was sent a list gets one short email asking them to delete it (never on a dry run, and not when the same host is saved again). README's list of automatic emails updated. The open question of whether "Save without emailing anyone" should also hold back host emails is in TODO.md.
- [x] **Polls on the booking form** — The booking form shows each open poll (optional) with the same ranking list as the manage page, now one shared module (`astro/ranking.ts`). Only a list the person has rearranged is sent, so nobody is counted in by default; rankings are checked before the registration is saved and stored with it. No suggestions there, as the address is not confirmed yet. e2e checks, plus a jsdom and axe run of both forms (0 violations); `astro check` clean.
- [x] **Polls: an invitation in the joining instructions, and DMARC on replies** — Joining instructions (and the reminder sent to anyone who registers again) end with "Have your say: …" for each open poll the person has not answered, with the manage button relabelled; no new email kind, and the admin page says so. Replies to suggestion emails are refused at SMTP time when Cloudflare's topmost `Authentication-Results` header records a DMARC result other than pass; headers further down (the sender's own) are ignored, and a missing header refuses nothing, as it has been reported missing on Worker delivery.
- [x] **Turnstile: action and hostname** — The booking form's widget now has `data-action="eventsandeye-register"`, and the server refuses a token unless siteverify reports that action and the host the registration was posted to, so a token solved on another site or form sharing the widget key no longer passes. Unit tests in `tests/turnstile.test.mjs` (siteverify stubbed).
- [x] **Markdown renderer nits** — Code spans are held aside like links, so nothing in them becomes emphasis; italics need the `*` to hug words and not sit inside a word or number (`2*3*4` stays as typed); link URLs may contain balanced brackets (Wikipedia-style). Three new tests in `tests/markdown.test.mjs`.
- [x] **Polls with a "count me out" line, registrant suggestions and email-reply moderation** — Registrants rank a poll's options on their manage page (most wanted first) and move a line under the ones they would join; the admin page tallies who would join, who would stay at home, first choices and a preference score, with names. Registrants can suggest their own option and rank it at once; the organiser is emailed and replies `yes`, `no` or `use <wording>` (Cloudflare Email Routing → the cron Worker's new `email()` handler, accepted only from an organiser address with a reference signed by `TOKEN_SECRET`), or decides on the admin page; wording that matches an existing option merges the suggestion and keeps everyone's ranking. Migration 0006, `src/polls.ts`, `src/inbound.ts`, new e2e checks and `tests/inbound.test.mjs`. The sent log gains poll totals (no names). Automatic replies (out-of-office) are dropped without a reply or bounce; only a whole-line answer counts; only the headers are read until sender and reference check out, and HTML is read in linear time. Polls are deleted with the 30-day retention. An independent review's findings (From-header display-name spoofing, parallel suggestions beating the caps, ballot races with merges) are fixed, with unit tests in `tests/polls.test.mjs`. Nothing emails registrants; ballots are deleted with the registration.
